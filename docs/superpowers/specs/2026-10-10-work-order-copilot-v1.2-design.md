# 工单辅助研判 V1.2 设计

日期：2026-10-10
状态：已按用户“开始进行”进入实现
范围：本地单用户、只读模拟工单；复用现有故障分析任务、报告与人工评测能力。

## 目标用户流程

1. 用户在 Web 工单台查看模拟工单列表、设备上下文、告警与数据质量提示。
2. 用户选择工单并启动故障分析。服务只读取工单数据，将工单字段映射为现有 `fault_analysis` 输入，并记录工单与任务的关联。
3. 用户查看分析报告及引用证据，选择对应任务提交“接受建议 / 需补充信息 / 不采纳”之一，可附审核人和备注。
4. 页面展示关联任务及审核记录，保留任务、报告和人工结论的可追溯链。

## 数据和安全边界

- 仅提供包内固定的合成工单数据，标注为演示数据；不访问真实企业系统或遥测。
- 工单连接器只读；没有设备控制、参数下发、现场操作步骤或安全规程替代能力。
- 使用 SQLite 迁移新增工单分析关联和追加式审核事件，支持同一工单多次分析和同任务多次审核。
- 工单启动分析复用现有持久任务队列和幂等键。工单 ID 作为显式任务来源元数据保存，不混入设备运行条件。
- 人工审核属于本地记录，不代表授权身份，也不代表工单处理结果已在外部系统执行。

## 接口契约

- `GET /api/work-orders?status=&q=`：工单列表、过滤结果和统计；合成数据标记始终可见。
- `GET /api/work-orders/{work_order_id}`：工单详情、关联任务、可用报告摘要及审核状态。
- `POST /api/work-orders/{work_order_id}/analyses`：映射工单字段，使用现有 runner 创建 `fault_analysis` 任务；支持 `Idempotency-Key`。
- `PUT /api/work-orders/{work_order_id}/analyses/{task_id}/review`：保存 verdict、reviewer、note；审核事件追加写，重复审核生成新版本。
- 不创建企业工单、不写设备数据、不触发外部副作用。

## 前端

- 新增 `/work-orders` 工单工作台，采用现有 Gridline 工业编辑式视觉语言：筛选/队列、工单严重性与状态、设备及告警上下文、数据完整性提示。
- 详情区展示关联分析进度和报告入口；分析未完成时只显示状态，不提供审核提交。
- 完成后允许人工选择审核结论、填写 reviewer 和备注，展示最新审核与历史版本。
- 从报告页可回到来源工单；移动窄屏下列表和详情纵向排列。

## 验收

- 合成工单可从 UI 列表打开并查看稳定 ID、设备、症状、告警时间和缺失字段。
- 创建分析后任务输入正确映射，来源关联在任务恢复/页面刷新后仍可查。
- 未完成或不属于该工单的任务不能审核；缺失 reviewer、非法 verdict、超长 note 被拒绝。
- 审核记录保留时间、reviewer、verdict、note 和递增版本；再次审核不覆盖历史。
- 工单 API 和 Web 构建可在无模型密钥时使用；仅真正启动分析需要现有模型配置。

## 不在本次范围

真实 CMMS/ERP、设备遥测、定时监控、团队账号/RBAC、多租户、联网部署、工单自动下发、参数写入和无人值守决策。
